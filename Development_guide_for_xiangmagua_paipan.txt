--------------------------------------------------------------------------------

4. 核心算法
--------------------------------------------------------------------------------

[4.1] 洗牌 makeDeck()
  生成 18 张牌：每种牌 2 张
  有朝向的牌每张独立随机 ↑/↓
  Fisher-Yates 洗牌

[4.2] 先天盘 makeXiantian(deck)
  g = {}; 每个宫位初始化为 [null, null]（精简）或 [null,null,null,null]（完整）
  FOR i = 0 .. 17:
    [gong, slot] = XT_ORDER[i]
    g[gong][slot] = deck[i]
  RETURN g

[4.3] 后天盘 makeHoutian(src)
  深拷贝 g
  若 baseName(中[0]) == baseName(中[1]) → 先后天一致，直接返回

  hand = 中[0]
  中[0] = 中[1]
  中[1] = null

  WHILE (最多 200 次):
    hn = baseName(hand)
    IF hn == '' → BREAK

    在外八宫 (OUTER) 寻找同名牌（忽略朝向）:
      found, fIdx = 定位

    IF !found → BREAK

    若 hand 有朝向: 对齐 found 宫位同类牌的朝向

    与 found 宫位另一张牌交换:
      other = 1 - fIdx
      tmp = g[found][other]
      g[found][other] = hand
      hand = tmp

  中[1] = hand
  RETURN g

[4.4] 活八门九星 addHuopan(g, date)  【仅完整版】
  sc = 时辰; jq = 节气; dun = 阴阳遁
  sg = 时辰宫
  isYang = (时辰属于阳时辰)

  menCard  = isYang ? 中[0] : 中[1]
  xingCard = isYang ? 中[1] : 中[0]
  initMen  = MEN_OF[baseName(menCard)]
  initXing = XING_OF[baseName(xingCard)]

  八门：从时辰宫起，阳顺阴逆，按 MEN_SEQ 铺到外八宫 [2]
  九星：从时辰宫起(洛书顺序)，阳顺阴逆，按 XING_SEQ 飞布九宫 [3]

[4.5] 抽签 / 活盘 doLive()
  deck = makeDeck()
  picked = [deck[0], deck[1], deck[2]]
  nature = CARD_NATURE[baseName(picked[2])]
  gong   = NATURE_GONG[nature]
  渲染三张牌 + 第三张的宫位/性质

[4.6] 终身盘 buildLifetimeCards(xt)  【仅完整版】
  先天卦换算模式的映射：
    命宫 ← 中[0]     身宫 ← 中[1]
    根   ← 震[0]     苗   ← 离[0]
    花   ← 兑[0]     果   ← 坎[0]
    子 ← 坎[1]    丑 ← 艮[0]    寅 ← 艮[1]
    卯 ← 震[1]    辰 ← 巽[0]    巳 ← 巽[1]
    午 ← 离[1]    未 ← 坤[0]    申 ← 坤[1]
    酉 ← 兑[1]    戌 ← 乾[0]    亥 ← 乾[1]

[4.7] 命宫计算 calcMingGongZhi(birthDate)  【仅完整版】
  月支序数 + 时支序数 = sum
  sum ≤ 14 → idx = 14 - sum
  否则     → idx = 26 - sum
  命宫地支 = ZHI_ORDER12[idx - 1]

[4.8] 字号自适应 fitPanFonts()  【完整版 / 精简版】
  根据宫格实际宽度动态设置 CSS 变量：
    --pan-font-size   = clamp(w/5.5, 10, 24)
    --gong-name-size  = clamp(w/9.5,  9, 16)
    --nature-size     = clamp(w/2.4, 26, 68)
  触发：渲染后、resize、orientationchange、ResizeObserver

[4.9] Canvas 导出 drawPanCanvas(g, title, opts)
  布局：
    ┌──────────────────────────┐
    │       标题（Qiji 26px）    │
    │   时间：xxx（Qiji 17px）   │
    │                          │
    │   九宫 3×3（格 150×150）  │
    │                          │
    │   问题：xxx（宋体 17px）  │

  opts = { question, duanyu, timeStr }
  画布高度 = 顶部 + 九宫 + 底部（自动测量）

    { type: 'xiangma-request-save' }
    ↓
  iframe 内集成脚本生成 payload:
    { title, question, duanyu, timeStr,
      xiantian: { dataURL, width, height },
      houtian:  { ... },
      lifetime: { ... } | null,
      lifetimeMode: 'convert' | 'fresh' }
    ↓
  iframe postMessage 回父窗口:
    { type: 'xiangma-save-case', payload }
    ↓

    1. 确保 案例/ 和 案例/attachments/ 目录存在
    2. 写入 PNG 文件（vault.createBinary / writeBinary）
    3. 生成 md 内容（frontmatter + 图片引用）

    5. 弹出 Notice 提示

7. HTML 内嵌集成代码
--------------------------------------------------------------------------------

[7.1] 主 IIFE 末尾暴露内部 API（关键！）
  在主 IIFE 的 })(); 之前加入：

    window.__x_state = state;
    window.__x_fmtTime = fmtTime;
    window.__x_drawPanCanvas = drawPanCanvas;
    window.__x_drawLifetimeCanvas = drawLifetimeCanvas;

  【重要】必须放在主 IIFE 内部，且 state / fmtTime / drawPanCanvas /
  drawLifetimeCanvas 已在同一作用域声明。

[7.2] 独立的集成 IIFE（放在 </script> 前）
  监听父窗口消息，构建 payload 并回传：

    (function(){
      const inIframe = (window.parent !== window);

      if (inIframe) {
        window.parent.postMessage({ type: 'xiangma-ready' }, '*');
      }

      window.addEventListener('message', function(e){
        if (e.data && e.data.type === 'xiangma-request-save') {
          try {
            const payload = buildSavePayload();
            window.parent.postMessage({
              type: 'xiangma-save-case',
              payload: payload
            }, '*');
          } catch (err) {
            window.parent.postMessage({
              type: 'xiangma-error',
              message: String(err.message || err)
            }, '*');
          }
        }
        if (e.data && e.data.type === 'xiangma-refocus') {
          try {
            window.focus();
            const lastActive = document.activeElement;
            if (lastActive && lastActive.tagName === 'TEXTAREA') {
              lastActive.focus();
            }
          } catch (err) {}
        }
      });

      function buildSavePayload() {
        // 读取 window.__x_state 和 window.__x_*
        // 生成 payload
      }
    })();

[7.3] 常见错误排查
  错误：state is not defined
  原因：集成代码在主 IIFE 外，访问不到 state
  解决：主 IIFE 里加 window.__x_state = state，集成代码用
        window.__x_state

  错误：fmtTime / drawPanCanvas is not defined
  同上，加 window.__x_fmtTime / window.__x_drawPanCanvas

  错误：保存失败：参数类型错误
  原因：writeBinary 需要 ArrayBuffer，不是 Buffer
  解决：Uint8Array → .buffer

  错误：切回排盘后 textarea 无法输入
  原因：iframe 在页面切换时丢失焦点
  解决：switchPage('pan') 时调用 iframe.contentWindow.focus()

9. 关键设计决策
--------------------------------------------------------------------------------

[9.1] 为什么用 IIFE？
  避免全局污染，与宿主页面（Obsidian、其他脚本）隔离。

[9.2] 为什么用 window.__x_* 暴露？
  集成代码在主 IIFE 外，通过 window 桥接内部作用域。

[9.3] 为什么用 display 而非 visibility 切换页面？
  早期版本用 position:absolute + visibility:hidden，但 Obsidian
  的样式覆盖会破坏。display:none 更稳定可靠。

[9.4] 为什么 .xiangma-page 用绝对定位而非 flex？
  两个 .xiangma-page 同级子元素，用 flex 时一个 display:none，
  另一个的高度仍可能因 flex 计算而塌陷为 0。
  绝对定位贴合父容器更可靠。

[9.5] 为什么牌面 DOM 拆 3 层 span？
  .card-text > (.card-sym + .card-body > (文字 + .card-face))
  竖排时符号/牌名/箭头可各占一行；
  颜色作用于外层，其余继承；
  复制文字时不带符号。

[9.6] 为什么朝向用 ↑ ↓ 而非 ^ v？
  Unicode 箭头更直观，宽度一致，复制时清晰。

[9.7] 为什么用 CSS 变量？
  昼夜模式只需切 body.dark，无需重建 DOM。
  字体自适应只需改 CSS 变量，所有子元素自动跟随。

[9.8] 为什么 Canvas 导出用 fillText 而非 strokeText？
  书法字体笔画细，加描边会发虚；
  只填充 + bold 权重即可清晰。

[9.9] 为什么问题/断语在导出时读取？
  允许用户排完盘后慢慢写，不受起卦顺序影响。

[9.10] 为什么用 srcdoc 加载 HTML（Windows 兼容）？
  老版 Chromium（Obsidian 内置）对 app:// 协议的 .html
  文件做 MIME 类型校验，如果不是 text/html 就拒绝渲染。
  fetch 不检查 MIME，拿到内容后用 iframe.srcdoc 注入可绕过。

[9.11] 为什么断语摘要与完整分开？
  未展开时显示摘要（前 60 字），展开时隐藏摘要只显示完整。
  避免重复阅读同一段文字。
  实现：展开时 summaryEl.style.display = 'none'，
        收起时 summaryEl.style.display = ''。

[9.12] 为什么盘面图片用 flex: 1 1 280px？
  同一套布局在宽屏（≥ 580px）自动并排，在窄屏自动换行竖排。
  比 JS 检测窗口宽度更简洁、更可靠。
